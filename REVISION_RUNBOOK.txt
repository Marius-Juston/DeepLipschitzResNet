The launcher validates the source hash, runs a GPU profile, then starts four
resumable workers. UCI jobs precede CIFAR-10. Per user authorization on
2026-10-03, the campaign has no wall-time or GPU-hour limit and the initial
profile has no timeout. The 792 job definitions, epoch caps, and early stopping
are unchanged. Failures still require inspection; unlimited time does not
mean every job will succeed. Resource use and progress remain recorded.
Profiling failures stop the launcher. Its completion marker skips profiling
on normal resumes. Do not delete it merely to rerun the launcher.
The unstarted manifest was migrated to the updated queue digest; the previous
manifest and queue source are in revision_artifacts/unlimited_campaign_migration/.
For new manifests, --hours 0 --gpu-hours 0 disables both limits.

Monitor:
  uv run --locked python revision_experiments.py status --out runs/revision_campaign
  tail -f revision_campaign.log
Workers write worker.log, atomic result/error JSON, and epoch snapshots beneath
runs/revision_campaign/jobs/. The status JSON records controller and worker PIDs.
This is a local monitor; it does not send messages or promise to wake an assistant.

Pause the training queue by sending SIGTERM to the controller_pid recorded in
runs/revision_campaign/status.json. The controller stops its workers and records
paused jobs; training resumes from the last completed epoch. Do not kill only
the outer launcher shell and assume its worker processes stopped. During the
initial profile, use the launcher log/process tree to identify the profile process;
the profile no longer has a time limit.

Resume training directly without repeating profiling:
  nohup uv run --locked python revision_experiments.py run --gpus 0,1,2,3 --out runs/revision_campaign > revision_resume.log 2>&1 &
Completed jobs are skipped. Inspect failed jobs before using --retry-failed.
Code hashes must match: changing training code requires a new manifest and
separate evidence. Never mix results from different source revisions.
